来源：open.italent.cn 文档中心的公开错误码表（`https://open.italent.cn/api/ErrorCode/Search`，共 276 条）、各接口文档的「限流」「错误码」「异常示例」栏、
社区文档「401/403 排查」「受信 IP 白名单」「429」（users.italent.cn pageId 80117962 / 95813698 / 109711678）。抓取于 2026-09-11。
**未用真实凭证验证**。标「无凭证探测（2026-09-11）」的是用伪造参数打出来、复跑两次一致的结果（命令见 `beisen-workspace/probe-log.md`）；

## 1. 三层错误

| 层 | 长什么样 | 在哪判断 |
|---|---|---|
| 网关层（鉴权、IP、限流） | HTTP 400 / 401 / 403 / 429 / 500，body 是 `{"message": "..."}` 或 `{"error": "..."}`，**没有 `code`** | 先看 `resp.status_code` |
| 业务层 | HTTP 200（⚠ 业务失败时的 HTTP 状态文档未说明，只给了 body），body 里 `code` ≠ 200 | 读 `code` / `Code`，统一转字符串 |
| 批量逐条 | 外层 `code` 为 200，但 `data.failDatas[]`、`data.failCount`、`data[].code` 表示部分失败 | 每个批量接口单独处理 |

## 2. HTTP 状态与网关错误

| 状态 | body | 含义 / 处理 | 来源 |
|---|---|---|---|
| 400 | `{"error":"invalid_tenantid"}` | 换 token 时 tenant_id 无效 | 无凭证探测（2026-09-11） |
| 400 | `{"message":"Authorization header is empty"}` | 业务接口没带 `Authorization` 头 | 无凭证探测（2026-09-11） |
| 401 | `{"message":"un-authorized"}` | token 无效 / 过期；**不存在的路径也返回 401**（先鉴权后路由） | 无凭证探测（2026-09-11） |
| 401 | — | 错误码表 OpenPlatform `401`：「调用接口没有权限」；排查项（文档原文）：域名是否正确、是否拿沙箱 token 调生产、token 是否过期、**连接器是否勾选了该接口**、是否配置了 IP 白名单、HTTP 方法是否与文档一致、不支持 Path 可变参数 | 文档原文，未实测 |
| 403 | 「当前企业已设置OpenAPI调用受信IP，当前调用端的IP不在受信IP范围内」 | 调用方出口 IP 不在受信 IP 名单；在开放平台管理者后台加 IP（立即生效） | 文档原文，未实测 |
| 429 | ⚠ 文档未给 body | 「超过接口限频次数」；也可能是租户**当日总量**用尽（见第 5 节） | 文档原文，未实测 |
| 500 | 空 body，状态行 `Falied to verify your credentials` | **旧版 v2.0 路径**（`/tenantbase/v1/{tenantId}/…`）带无效 token 时的表现 | 无凭证探测（2026-09-11） |
| 500 | `{"data":null,"code":"500","message":"系统错误"}` 等 | 内部服务器异常（各接口错误码栏：「需结合具体情况」「请联系北森技术人员」） | 文档原文，未实测 |

响应头：无凭证探测（2026-09-11）看到每个响应都带 `X-PAAS-Request-ID`、`EagleEye-TraceID`；token 接口还带
`X-RateLimit-Limit-second: 400` / `X-RateLimit-Remaining-second`。**报障时把 `X-PAAS-Request-ID` 和 `EagleEye-TraceID` 记进日志**；
异步接口必须用 `X-PAAS-Request-ID` 查结果（见 `auth-and-conventions.md` 第 7 节）。业务接口是否也返回 `X-RateLimit-*` 头 ⚠ 未知（无凭证只看到 token 接口有）。

## 3. 业务 `code`

各接口文档错误码栏的共同说法：

| code | 含义（文档原文） | 处理 |
|---|---|---|
| `200` | 业务成功 | 仍要检查批量接口的逐条结果 |
| `417` | 「业务异常，参数异常」「参数异常、业务不合法」 | **不要重试**，把 `message` 原样记下来改参数 / 改数据 |
| `400` | 招聘接口：「参数错误，解决方式：根据message中的提示修改相关传入数据」 | 同 417 |
| `500` | 「内部服务器异常」 | 有限次退避重试；持续出现联系北森（`supportapi@beisen.com`，「重要升级通知」中给出的标准 API 咨询邮箱） |
| `206` / `401` / `417` | 假勤推送类接口的 `Code`：「200 成功 206 部分成功 401 无权限 417 失败」 | 206 按部分失败处理 |

`code` 的类型因产品线不同：组织员工是字符串 `"417"`，招聘是整数 `400`，假勤推送是首字母大写的 `Code`（见 `auth-and-conventions.md` 第 5 节）。

文档里常见的 417 message（原文，便于日志检索）：
- `只支持查询90天范围内的数据，请分段查询`（所有时间窗接口）
- `Value cannot be null.\r\nParameter name: Argument name: Ids is null`（按 ID 查询没传 oIds）
- `一次操作不能超过30条数据`（工号 / 手机号反查）
- `OIds所有元素必须为大于等于0的整数`、`OId必须大于等于0`、`OrgOId不能为空且为正整数！`
- `电子邮箱与待入职的内部员工：…重复，请确认信息！`（新建员工）
- `该人员当前状态不能办理当前业务`（入职）、`非试用员工不支持试用期转正操作`、`外部人员不支持离职操作`、`指定的直线经理不存在`
- `根据内部ID和对象匹配到多条数据`（外部 ID 映射）
- 假勤：`ApproveStatus参数格式不正确,请参考接口文档修改后重试！`、`PageSize参数必须大于0!`、`休假记录不能为空！`、`后台服务发生未知错误，请联系北森公司进行处理!`
- 招聘：`开始时间不能大于等于结束时间`、`一次最多允许查100个`、`要转移的流程和当前流程不一致，不允许转移`

## 4. 公开错误码表

`GET https://open.italent.cn/api/ErrorCode/Search?page=1&perpageCount=30`（文档站自己的匿名接口，`perpageCount` 最大 30，2026-09-11 共 276 条 / 10 页）。
按应用分布：TenantBase 102、Attendance 79、Ocean（报表）49、Nusion（页面 / 组件平台）29、Compensation 14、OpenPlatform 3。

| 前缀 | 应用 | 例子（`errorCode` · `describe`） |
|---|---|---|
| `00908-01xxxx` | TenantBase（组织员工） | `00908-010011` 默认方案不允许删除；`00908-010022` 删除组织编制时，存在审批中的记录；`00908-010024` 组织不能为空 |
| `00909-xxxxxx` | Attendance（假勤） | `00909-001004` 单批次推送数据量不能大于{0}条；`00909-001007` 参数{0}，不可为空；`00909-001009` 导入任务执行中,请稍后再试；`00909-030040` 短时间内重复操作，或者当前没有执行完 |
| `00960-26xxxx` | Compensation（薪酬） | `00960-260003` 薪资包不存在或已停用；`00960-260005` 该员工不存在启用的发薪的薪资档案 |
| `401` / `403` / `429` | OpenPlatform（网关） | 见第 2 节 |
| `f05xx-` / `f08xx-` | Ocean / Nusion | 报表、页面平台内部错误，集成场景少见 |

⚠ 文档未说明：这些 `00908-…` / `00909-…` 长错误码与接口响应里 `code` 字段（`"417"`）的关系——各接口的异常示例只出现 `417`，
长码可能出现在 `message` 或别的字段里，拿到凭证后核实。数据源接口另有自己的码：`000001` 参数缺失、`000002` 参数过长、`1000024` listFilter 超过 10 个。

## 5. 限流

**规则**（429 文档原文）：「北森开放平台的每个接口都有对应的频率限制要求，例如……50次/秒/企业 1500次/分钟/企业……
（限频统计的是单位时间内本租户对于本接口的调动次数，如果某租户下，多个连接器都都包含了X接口，那么对于X接口，单位时间内多个连接器累积调用次数不可超过其限频次数）。
此外，每个租户每日接口调用总次数也有频率上限，超过频率上限，该租户当日调用所有接口都会返回429」。

要点：
- **按「租户 × 接口」计数，多个连接器 / 多个系统共享同一额度**。你的同步程序和客户另一个集成商的程序会互相挤占。
- **每日总量**上限存在，但具体数值在「openapi和内网api的每日调用次数查询」页，⚠ 未抓取（需登录的后台查看，文档未公开数字）。用尽后当天**所有接口**都 429。
- 每个接口的限额写在各自文档的「限流」栏。抓到的 v3.0 文档里最常见的档位：

| 档位（次/秒/企业 · 次/分钟/企业） | 出现次数（组织员工 / 假勤 / 招聘 / PaaS） |
|---|---|
| 50 · 1500 | 251 / 115 / 86 / 50 |
| 20 · 1000 | — / — / 89 / — |
| 20 · 1200 | 5 / 18 / 1 / — |
| 25 · 750 | — / 7 / — / — （如 `AttendanceStatistics/GetAttendanceStatisticsList`） |
| 30 · 500 | 6 / — / — / — （如 `Employee/Transfer`） |
| 30 · 200 | 5 / — / — / — |
| 1 · 6 ~ 1 · 60 | — / — / — / 11（PaaS 部分接口） |

- 注意**分钟额度常常比「秒额度 × 60」小得多**：50/秒 看着宽松，但 1500/分钟 平均只有 25/秒。按分钟额度做限速。
- 本 skill 各 reference 在每个 endpoint 下写了它的限额；其余接口查文档「限流」栏。

## 6. 其他时间类限制（文档原文）

| 限制 | 出处 | 后果 |
|---|---|---|
| 滚动查询两次调用间隔 ≤10 秒 | 组织员工所有时间窗 / 滚动接口 | 超时后「查不到下批次数据」——静默少数据 |
| 时间窗 ≤90 天 | 同上 | 417 `只支持查询90天范围内的数据，请分段查询` |
| 相同参数 3 秒内只能请求一次 | Transfer、Dimission、DimissionApproval、ProbationPositive | 报错（message ⚠ 文档未给） |
| 假勤部分查询一次只能一天 | 休假按审批时间、考勤记录 | ⚠ 示例与警告矛盾，按一天处理 |
| 异步任务状态轮询不能太密 | AsyncApiExecInfo/GetByRequestId（50/秒、1000/分钟） | 「超出限频后无法继续轮询」 |
| 下载链接 30 天有效 | 招聘附件 `downloadUrl`、入职资料 `*DownLoadUrl` | 过期后需重新取 |

## 7. 重试策略

| 情况 | 重试？ |
|---|---|
| 401 | 强制重新换 token，**只重试一次**；仍 401 按第 2 节排查（连接器勾选 / 沙箱生产 / IP） |
| 403 受信 IP | 不重试，加白名单 |
| 429 | 指数退避（如 1s、2s、4s… 上限 60s），并降低并发；若持续到次日才恢复，多半是每日总量 |
| 417 / 400 | 不重试 |
| 500 / 网络超时 | 读接口退避重试 2~3 次；**写接口先查再重试**（避免重复创建），且间隔 >3 秒 |
| 异步推送 `Code: 200` | 不是成功，去查 `X-PAAS-Request-ID` 的状态 |

```python
import time, random, requests

def call_with_retry(client, path, payload, is_write=False, max_retry=3):
    delay = 1.0
    for attempt in range(max_retry + 1):
        try:
            return client.post(path, payload)          # 401 重取 token 已在 client.post 内处理
        except requests.HTTPError as e:
            status = e.response.status_code if e.response is not None else None
            if status == 429 or (status and status >= 500 and not is_write):
                if attempt == max_retry:
                    raise
                time.sleep(delay + random.random()); delay = min(delay * 2, 60)
                continue
            raise
        except RuntimeError as e:                      # 业务 code 417/400：不重试
            raise
```

限速建议（自选实现，不是文档要求）：按「接口路径」维护一个令牌桶，速率取该接口的分钟额度 / 60，并给同租户其他集成方留余量。
