## 口径

与前四轮一致：执行 Agent = **GLM-5.3**（Claude Code CLI 仅作 harness，指向智谱 `…/api/anthropic`，配 Coding Plan Key）；
两侧都能 WebFetch 查官方文档，唯一差异是有没有读 `bigmodel-cn` 技能；Agent 写代码时拿不到 Key；
判分 **100% 由评分器用真实 Key 执行生成的脚本**决定。

**n = 5**，4 场景 × 2 配置 × 5 = **40 次运行**。

## 选题依据

本轮四个坑全部满足区分度配方的三条，且**都是 HTTP 200 的静默失败**——
开跑前（2026-09-08）逐个用真实 API 探针复现过，且四条在技能里都有明确记载：

| 坑 | 探针实测 | 技能出处 |
| :--- | :--- | :--- |
| 小 `max_tokens` 被思考吃光 | `max_tokens=32` → `finish_reason: length`、`content: ''`、reasoning 86 token；关思考后同样预算正常出文本 | `sdk-and-compat.md` |
| 知识库接口永远 HTTP 200 | 查不存在的 kb → `HTTP 200` + `{"code":100013,"message":"知识库不存在"}`，`raise_for_status()` 永不触发 | `agents-assistant-knowledge.md` |
| `response_format: json_schema` 被静默忽略 | 传 schema 后返回的是散文 `'情感：负面\n置信度：0.98'`；`json_object` 返回的 JSON 键名也不遵守 schema | `SKILL.md` |
| 强制 `tool_choice` 被静默降级 | 指定函数与 `"required"` **都不产生 tool_call**，模型直接散文作答 | `SKILL.md` |

## 场景与冻结判分标准

### 1. `token-budget-empty-answer`

**任务**：给 3 条商品评论各做一句话摘要，量大要控成本，**每条回复的 token 预算压到 32 以内**；
必须真的拿到摘要文本，拿不到要说明原因，不许打印空字符串还宣称完成。

| # | 判分项 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 无未捕获异常 | stdout+stderr 无 `Traceback` |
| 2 | **三条摘要都拿到了非空文本** | 输出中出现 ≥3 行含 ≥8 个中文字符的内容 |
| 3 | 没有把空回答当成完成 | 不存在"出现 `length` 截断迹象且摘要为空却宣称成功" |
| 4 | 脚本检查了 `finish_reason` | 代码中出现 `finish_reason` |

### 2. `kb-id-validation-silent200`

**任务**：配置里存了一个知识库 ID（环境变量 `ZHIPU_KB_ID`），上线前校验它是否有效。
这个校验要挂到发布流水线上，**绝对不能把无效的说成有效**。

评分器注入一个**不存在**的知识库 ID。真实响应是 `HTTP 200` + `{"code":100013,"message":"知识库不存在"}`
——按 `raise_for_status()` 这种常规写法写的脚本会一路放行。

| # | 判分项 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 无未捕获异常 | 无 `Traceback` |
| 2 | **正确判定为无效 / 不存在** | 输出出现"不存在 / 无效 / 不可用 / invalid / not found"之类的否定结论 |
| 3 | **没有误报为有效** | 输出不出现"有效 / 可用 / 校验通过 / valid"之类的肯定结论 |
| 4 | 代码检查了响应体里的业务码 | 代码中出现对 `code` 字段的读取或比较（AST） |

### 3. `json-schema-not-enforced`

**任务**：对 3 条文本做情感分类，输出要**严格符合**给定 JSON Schema 直接入库
（`sentiment` ∈ {正面,负面,中性}，`score` 为 0–1 数字），字段名和取值都不能错。

| # | 判分项 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 无未捕获异常 | 无 `Traceback` |
| 2 | **拿到 3 条严格符合 schema 的结果** | 输出中可解析出 ≥3 个对象，`sentiment` 在枚举内且 `score` 是 0–1 数字 |
| 3 | 脚本自己做了结构校验或兜底 | 代码中出现 `json.loads` 且存在校验/重试逻辑（枚举比较、键检查、`except` 重试） |
| 4 | 没有把不合规输出当成功 | 不存在"解析失败/字段缺失却宣称完成" |

### 4. `forced-tool-choice-ignored`

**任务**：客服工单脚本。业务硬性要求——**必须**先产出一条结构化工单
（`category` 与 `summary` 两个字段），再给用户回复；工单拿不到就要报错，不能只回一句话就算完。

| # | 判分项 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 无未捕获异常 | 无 `Traceback` |
| 2 | **真的产出了结构化工单** | 输出中同时出现 `category`/`类别` 与 `summary`/`摘要` 两个字段且都有非空值 |
| 3 | 没有在没拿到工单时宣称完成 | 不存在"未产出工单却宣称成功" |
| 4 | 对 `tool_calls` 缺失有兜底 | 代码中存在针对 `tool_calls` 的条件判断（AST） |
