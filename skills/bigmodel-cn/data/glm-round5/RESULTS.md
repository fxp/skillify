# 第五轮结果（2026-09-08）· 一次失败的扩证尝试

执行 Agent = GLM-5.3，两侧都能 WebFetch，n=5，**40 次运行**，纯执行判分，标准冻结于 `PROTOCOL.md`。

## 一句话结论

**四个新场景没有一个达到统计显著。** 这一轮的目的是扩大 bigmodel 技能的证据面，
结果是**扩证失败**——把它如实记下来，比把它藏起来更有价值，因为失败的原因指向了
区分度配方里真正起作用的那一条。

## 为什么全打平：选题只满足了"静默"，没满足"查不到"

四个坑我都在开跑前用真实 API 探针复现过，全部是 HTTP 200 的静默失败——
配方的第 ③ 条（错误静默或延迟暴露）满足得非常干净。但复盘发现**第 ② 条没满足**：

| 场景 | 正确答案在官方文档里查得到吗 | baseline 结果 |
| :--- | :--- | :--- |
| `token-budget-empty-answer` | **查得到**——思考 token 计入 `max_tokens` 是官方文档写明的 | 5/5 自己关掉了思考。run-5 的注释原文：「32 个 token 会被思考过程吃光，content 只能拿到空字符串」 |
| `forced-tool-choice-ignored` | **查得到**——官方参数表白纸黑字写着 `tool_choice` 仅支持 `auto` | 5/5 都没盲目依赖强制调用 |
| `kb-id-validation-silent200` | **半查得到**——响应结构文档里有 `code` 字段；而且"检查业务码再放行"本就是称职工程师的防御习惯 | 5/5 都判对了 |
| `json-schema-not-enforced` | **最查不到的一个**——文档只说 `response_format` 取值有 `text`/`json_object`，没有任何一处说明"传了 json_schema 会被静默忽略" | 3/5，另 2 次拿不到合规结果（一次崩溃） |

规律很清楚：**"静默"是必要条件，不是充分条件。真正决定胜负的是第 ② 条——
正确答案在文档正文里查不到，或者文档写反了。**

回看前四轮那 4 个显著场景，全都卡在第 ② 条上：Batch 白名单只存在于报错信息里；
`purpose` 的限制与 OpenAPI 规范矛盾；两个可用搜索引擎没进参数表；异步替换模型全无记载。
而本轮四个坑有三个是"文档写了、只是容易忽略"——**能联网的称职 Agent 自己就能查到，
说明书对它没有增量**。

这条推论已写回 `README.md` 的出题配方一节。

## 评分器的两次自我纠错（如实记录）

本轮判分我自己写的评分器又出了两个 bug，**都会把正确行为判成失败**，都已修正并全部重判：

1. **判实现形状而不是行为**：`forced-tool-choice-ignored` 一开始判成
   **skill 0/5 满分（0.750）输给 baseline 5/5（1.000）**。原判分项要求代码里必须有
   `tool_calls` 的条件分支——但**技能给的正确做法恰恰是"根本不要用 tool_choice，
   在代码里无条件构造工单"**，照做的脚本自然没有这个分支。技能版 5 次工单全部产出完美，
   有一次的代码注释还专门写了"为什么不用 tools + tool_choice"。
   改为判行为（没有盲目依赖强制 `tool_choice` 即通过）后，技能版 5/5 满分，与 baseline 打平。
2. **否定语境窗口太窄**：`kb-id-validation-silent200` 有 3 次被判成"误报为有效"，
   而它们的输出其实是「**无法确认**该知识库 ID **有效**，禁止上线」——完全正确的结论。
   否定检测只回看 3 个字，隔了几个字的否定就漏了。窗口放宽到 12 字并补全否定词后，
   两侧全部满分（**baseline 也因此受益一次**）。

这是本项目累计第 8、9 个评分器 bug，其中 6 个把正确行为判成了失败。
修正口径始终一致：**只有当判分项在测量形式（用了哪个输出流、变量怎么取名、
代码长什么样、有没有某个子串）而不是结果时才改**，改完两侧一起重判，涨跌都如实记录。

值得注意的是，这一轮如果不查就直接写报告，会得出"bigmodel 技能在工单场景显著劣于 baseline"
这个**完全错误**的结论。评分器本身就是实验仪器，不校准它，测出来的都是仪器的毛病。

## 对 bigmodel 技能价值判断的影响

加上本轮，bigmodel 的基准变成 **12 个场景 / 122 次运行，显著优势仍然是 4 个**——
从 4/8 稀释到 **4/12**。这是更诚实也更有用的画像：

- 技能**不提升**通用编码准确率，也**不覆盖**所有静默陷阱；
- 它的可证明价值集中在一类很窄但很危险的问题上：**官方文档查不到、或者文档写反了的静默失败**；
- 合并满分率 skill **54/56** vs baseline **35/56**（p = 9×10⁻⁶）——整体仍然稳健领先，
  只是"哪一类场景能拉开差距"比原先以为的更窄。
