公司决定在下一财年将客服体系整体迁移到智能化平台。现有的人工坐席共 320 人，分布在三个城市的呼叫中心，日均处理工单约 4.2 万件，其中约 63% 属于可标准化应答的常见问题，例如订单查询、退换货政策、发票开具与物流跟踪。

迁移分三个阶段推进。第一阶段为期四个月，目标是把上述常见问题中的 40% 交由自动应答处理，人工坐席转为审核与兜底；第二阶段再用六个月把比例提升到 70%，同时上线多轮对话与工单自动分派；第三阶段为长期优化，重点是把满意度从当前的 82 分提升到 90 分以上。

技术选型上，团队评估了自建模型微调、采购成品客服系统、以及基于大模型 API 自研三条路线。自建微调的一次性投入约 480 万元，周期 9 个月，且需要长期维护算法团队；采购成品系统年费约 220 万元，但定制能力受限，历史工单数据难以完整接入；基于大模型 API 自研的首年成本估算在 90 万至 140 万元之间，主要变量是调用量与模型档位。

风险方面，最需要关注的是应答准确率不足导致的投诉升级。历史数据显示，一次错误的退款政策应答平均会带来 2.7 次后续联系，并使该用户当月复购率下降 11 个百分点。因此上线前必须建立离线评测集，覆盖至少 2000 条真实工单，准确率低于 92% 不予放量。

数据合规是另一条硬约束。工单中包含姓名、手机号、收货地址与部分支付信息，按照公司信息安全规范，这些字段在送入外部接口前必须完成脱敏，且脱敏后的映射关系只能保存在内网数据库中，保留期不超过 90 天。

人员安排上，预计第二阶段结束后可释放约 130 个坐席编制。公司的方案不是裁员，而是将其中约 80 人转岗到质检与知识库运营岗位，负责维护应答话术、标注错误案例、以及持续扩充离线评测集；其余约 50 人通过自然减员消化。

预算审批需要在本季度末完成。财务部门要求提供分阶段的投入产出测算，其中第一阶段必须给出明确的止损条件：若四个月后自动应答占比未达到 25%，或准确率持续低于 88%，项目转入评估期并暂停后续采购。
