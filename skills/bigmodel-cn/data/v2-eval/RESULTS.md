# v2 精简版说明书 · A/B 结果（2026-09-08）

## 一句话结论

**在总体节省 token 的前提下，准确率没有退步，还小幅提升。**
每做对一次的成本从 baseline 的 240,945 降到 **106,901（−55.6%）**，v1 是 127,679。

## 实验设计

唯一变量是说明书版本。任务文本从原轮次的 `run_agents.sh` **逐字抽取**，
harness 完全相同，判分用的是**各场景原来那一份冻结的评分器**（`grade_v2.py` 直接调用它们的
`run()` / `grade()`，不新写任何判据）。8 个场景 × n=5 = 40 次运行，
对照组直接复用既有的 v1 with_skill 与 baseline 记录。

场景覆盖全部 4 个统计显著场景（准确率不能掉）+ 4 个消耗大 reference 的打平场景。

| :--- | ---: | ---: | ---: |
| **v2 相对 v1** | **−12.9%** | **−14.1%** | 计费当量 **p = 0.019** ✅ / 线上 p = 0.14 |
| **v2 相对 baseline** | +18.3% | **−8.9%** | |

**说明书被读进上下文的体积砍了一半：46,885 → 22,129 字符（−52.8%）**，Read 次数也显著下降（p = 0.022）。

### 准确率

| | 满分率 | 平均分 |
| :--- | ---: | ---: |
| baseline | 19/40（47.5%） | 0.679 |
| v1 说明书 | 38/40（95.0%） | 0.979 |
| **v2 精简版** | **39/40（97.5%）** | **0.983** |

- **8 个场景无一退步**（逐场景核对）。唯一变化是 `pdf-reuse-fileid` 从 4/5 变 5/5。
- v2 vs baseline：Fisher **p = 4.0×10⁻⁷**。
- v2 vs v1：只差 1 次，**p = 1.0，不显著**——诚实的表述是"准确率保住了，没有证据说变好"。

## 边界，以及"节省 token"这句话到底能怎么说

- **相对 v1**：线上与计费当量都降（−12.9% / −14.1%），计费当量显著。这一条站得住。
- **相对 baseline**：只有**计费当量**是负的（−8.9%）；**线上总 token 仍然 +18.3%**。
  也就是说"比不用说明书更省 token"这句话**只在计入 cache 折扣时成立**，
  而该端点从不报告 cache 写入（折算对说明书有利，见 `token-cost/README.md`）。
  与供应商无关的硬数字仍然是"更贵 18%"。
- **准确率提升不显著**（39/40 vs 38/40，p = 1.0）。能证明的是**没有退步**，以及相对 baseline 的巨大优势。
- n=5、8 个场景、单一执行器（GLM-5.3），结论不外推。
