# v4 · 协议（开跑前冻结，2026-09-09）

## 从弱执行器轮学到的机制

`glm-4.5-flash` 上 v1=27/40、v2=22/40。查因：**v2 每次读入 42,266 → 33,795 字符，
各 reference 普遍读得更少**（tools.md 4,595→3,453，models.md 2,581→1,537）。
拆出去的 `chat-advanced.md` 只有 45% 的运行会去读，而 v1 里这些内容本来就在必读的 `chat.md` 里。

**结论：v2 省下来的 token，正是弱模型写对代码所依赖的上下文。**
强执行器（GLM-5.3）自己知道该读什么，所以不受影响；弱执行器不行。

## v4 的三处改动（每一处都对应上面的机制）

1. **保留**「静默陷阱速查表」——它是净增的决策性事实，成本低（+2.9k 常驻），
   在两个执行器上都没有观察到副作用。
2. **删掉**「读取纪律」一节——它明确劝阻通读，对弱模型是净损害。
3. **把 `chat.md` 合并回去**（撤销该拆分）——它是 100% 必读的文件，拆掉等于直接抽走上下文。
   **保留**知识库那份的拆分——它只有 ~25% 的运行会读，拆分省 token 而不影响主路径。

## 达成标准（冻结）

在 `glm-4.5-flash` 上，同一批 8 场景 × n=5、同一份冻结评分器：
- **准确率**：v4 满分率 **> v1 的 27/40**
- **token**：v4 计费当量 **≤ v1**

两条同时满足才算达成；任一不满足如实记为失败。
