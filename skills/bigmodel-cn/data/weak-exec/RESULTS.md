# 弱执行器轮：四个版本的对照，以及一个负面结论（2026-09-09）

## 结论：**优化目标不成立。v1（未优化的原版）是四个版本里最好的。**

执行 Agent = `glm-4.5-flash`（明显弱于 GLM-5.3，且实测未被静默重路由），
8 场景 × n=5 = 40 次/版本，任务文本逐字相同，判分用各场景**原来那份冻结的评分器**。

| 版本 | 满分率 | 平均分 | 计费当量 | 每做对一次 |
| :--- | ---: | ---: | ---: | ---: |
| **v1（原版）** | **27/40** | **0.852** | **117,670** | **174,325** |
| v2（拆分 + 速查表 + 读取纪律） | 22/40 | 0.788 | 103,094（−12.4%） | 187,444（+7.5%） |
| v4（保留速查表，删读取纪律，合并回 chat.md） | 22/40 | 0.815 | 128,972（+9.6%） | 234,494（+34.5%） |

v2 vs v1：Fisher p = 0.36；v4 vs v1：Fisher p = 0.36。
**两个"优化版"在准确率上都不如原版，且每做对一次都更贵。**

## 为什么换弱执行器

前三轮都在 GLM-5.3 上测，满分率 92%~97%，**天花板效应**让 n=5 测不出任何差异。
换到 `glm-4.5-flash`，v1 只有 27/40（67.5%），**终于留出 32.5% 的失败空间**——
这才是能检验"说明书优化有没有用"的条件。空间是有了，但优化版没有吃下去，反而更差。

## 机制：省下来的 token 正是准确率所依赖的上下文

| | 每次运行 Read 读入 | chat.md 读入 | tools.md | models.md |
| :--- | ---: | ---: | ---: | ---: |
| v1 | 42,266 | 12,599（100% 必读） | 4,595 | 2,581 |
| v2 | 33,795 | 5,566（拆分后只剩核心） | 3,453 | 1,537 |

v2 拆出去的 `chat-advanced.md` 只有 **45%** 的运行会去读，而 v1 里这些内容本来就在必读的
`chat.md` 里。**强执行器自己知道该读什么，所以不受影响；弱执行器不行。**

v4 按这个机制做了针对性修正（删掉劝阻通读的「读取纪律」、把 `chat.md` 合并回去），
读入量确实回来了（wire +23.3%），**但准确率没回来**——说明问题不只是"读得少"。
剩下的嫌疑是**速查表本身**：v2 和 v4 都含它，都是 22/40；v1 不含，是 27/40。
一大块"这里有 20 个坑"的密集清单，可能在弱模型上挤占了它本该用来读真正接口文档的注意力。
这条没有进一步验证——四轮下来证据方向一致，继续调下去就是在数据上挑结果了。

## 四轮汇总：目标的两半各自的真实状态

| 轮次 | 执行器 | 对比 | token | 准确率 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | GLM-5.3 | v2 vs v1 | **−14.1%（p=0.019）** ✅ | 39/40 vs 38/40（p=1.0）**无变化** |
| 2 | GLM-5.3 | v3 vs v2 | +3.9% ❌ | 35/40 vs 37/40（p=0.71）**无提升** |
| 3 | glm-4.5-flash | v2 vs v1 | −12.4%（p=0.11） | 22/40 vs 27/40 **更差** |
| 4 | glm-4.5-flash | v4 vs v1 | +9.6% ❌ | 22/40 vs 27/40 **更差** |

**「省 token」在强执行器上成立且显著；「准确率提升」四轮全部未能证明，
且在有测量空间的弱执行器上，所有优化版都比原版更差。**

## 据此做的处置

**把线上的 `bigmodel-cn` 回退到 v1。** 理由：

- 准确率是这份说明书存在的意义，token 是次要指标；
- 强执行器上 v1 与 v2 打平（38/40 vs 39/40，p=1.0），v2 的 14% 节省买不到任何准确率；
- 弱执行器上 v1 明显更好（27/40 vs 22/40），且**每做对一次更便宜**（174,325 vs 187,444）；
- 综合两个执行器，v1 是唯一没有在任何条件下变差的版本。

v2 / v3 / v4 全部保留在 `bigmodel-cn-v2-archive/`、`bigmodel-cn-v3/`、`bigmodel-cn-v4/`，
连同各自的运行记录，供后续复查或换条件重测。

## 这轮真正的产出

不是一份更好的说明书，而是一条可复用的经验：

> **拆分 reference、加"只读你需要的那节"这类读取纪律，是在用准确率换 token。
> 换得划不划算取决于执行器强弱——强模型知道该读什么，省下的是冗余；
> 弱模型不知道，省下的是它写对代码所必需的上下文。**

如果要在弱模型上省 token，正确方向不是让它少读，而是**把决策性事实前置到它必读的那一份文件里，
同时不削减参考资料的完整性**——v4 试了前半段（速查表前置）但同时保留了速查表带来的干扰，
下一次该测的是"只前置、不加清单式速查表"这个更小的改动。
