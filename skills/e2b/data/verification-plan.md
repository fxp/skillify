# E2B skill — verification plan

Status: this skill (`../e2b/`) was produced from steps 1–2 of the `create-doc-skill` methodology only (fetch real docs, structure them into SKILL.md + references/). Step 3 (real API verification) and step 4 (with/without comparison) were **not done** — no E2B API key was available at authoring time (2026-09-21). This file is the priority-ordered list of what to test once a key is available, per `references/verify.md`'s "没有 key、或 key 权限不够时" fallback plan.

Cost/risk profile note: unlike a stateless REST API (e.g. Firecrawl), E2B bills **per second while a sandbox is Running**, and a forgotten *running* sandbox keeps costing money indefinitely (until it hits the plan's continuous-runtime cap) rather than just returning a cheap error on the next call. Every test below should end each sandbox with an explicit `kill()` in a `finally`/`try...finally` block, and the whole verification pass should be run under a fresh account's $100 free-credit allowance (or a small deliberately-capped budget) so a scripting mistake can't run up a real bill. Set a spending limit in the console budget tab before starting.

## Priority 1 — cheap, structural, "does the 30-second example even work"

These gate everything else; if wrong, most of the skill is wrong.

1. **Base install + first sandbox.** `pip install e2b` / `npm install e2b`, set `E2B_API_KEY`, run the exact SKILL.md "30-second first run" snippet in both languages. Confirm: sandbox creates, `sandbox_id`/`sandboxId` is a real ID, `commands.run('echo "hello from e2b"')` returns `stdout` containing the string and `exit_code`/`exitCode` is `0`, `kill()` succeeds without error. **Expected cost: a few seconds of a default 2 vCPU / 0.5 GiB sandbox, ~$0.0001.**
2. **Confirm default resource allocation.** Call `getInfo()`/`get_info()` on a freshly created sandbox with no custom template and check `cpuCount`/`cpu_count` and `memoryMB`/`memory_mb` actually equal 2 and 512 as the billing FAQ's worked example claims (`references/lifecycle-and-cost.md`).
3. **Confirm package name traps.** Deliberately try `npm install @e2b-dev/code-interpreter` (expected: 404 / not found) to confirm the "no such scope" claim is still accurate, then install the real `@e2b/code-interpreter` and `e2b-code-interpreter` (pip) and confirm both import cleanly (`from e2b_code_interpreter import Sandbox` for Python).
4. **REST API auth header.** One raw `curl` to `https://api.e2b.app` (a cheap read-only endpoint, e.g. `GET /sandboxes` or `GET /v2/sandboxes` for listing) with `X-API-Key: <key>` to confirm the header name/format from the OpenAPI `securitySchemes`, and one deliberately-wrong-key call to see the actual auth error shape (status code + body), since `references/errors-and-limits.md` currently has no confirmed HTTP-level error envelope.

## Priority 2 — the "intuition trap" claims that drive the cross-cutting rules in SKILL.md

These are the highest-value things to verify because they're exactly the claims an agent would otherwise get wrong by analogy to other platforms. Each corresponds to one `evals/evals.json` scenario.

5. **Timeout default + kill-on-expiry (eval scenario 1).** Create a sandbox with `timeout=10` (Python, i.e. 10 seconds) and no `lifecycle` override, sleep 15 seconds, then try `commands.run()` against it. Expect a `SandboxNotFoundException`/`SandboxNotFoundError` or similar — confirm the exact exception type and message. Then repeat with `lifecycle={"on_timeout": "pause", "auto_resume": True}` and confirm the sandbox is `Paused` (via `Sandbox.list(query={"state": ["paused"]})`) after the same wait, and that calling `commands.run()` again transparently wakes it (check `get_info().state` before/after, per the auto-resume example in `references/lifecycle-and-cost.md`). **Expected cost: negligible (few seconds of default sandbox each), plus normal pause/resume latency (~4s/GiB pause, ~1s resume — trivial at 0.5 GiB).**
6. **`Sandbox.connect()` timeout semantics — extend-only (SKILL.md rule 2).** Create a sandbox with a 20-minute timeout, then immediately `connect()` with the (5-minute) default and confirm via `get_info()`'s `end_at`/`endAt` that the expiry did **not** shrink to 5 minutes from now. This is a fast, cheap check (no waiting required, just compare timestamps).
7. **Code Interpreter state persistence across `run_code` calls (eval scenario 2).** In one sandbox, call `run_code("x = 42")`, then a second `run_code("print(x)")` and confirm `42` is in the output — this is the core claim behind cross-cutting rule 3 and the highest-value thing to confirm or refute, since it's the most commonly misunderstood part of code-interpreter SDKs generally (not E2B-specific intuition, but worth nailing down precisely for E2B's context model). Also test the negated case: `commands.run('export FOO=1')` then a second `commands.run('echo $FOO')` and confirm it prints empty/unset, confirming shell state does *not* persist (eval scenario 3).
8. **Billing state transitions (eval scenario 4).** Create a sandbox, note the time, `pause()` it, wait a couple minutes, `connect()` to resume, and check the console usage tab (or a lifecycle webhook if set up) to confirm no compute was billed during the paused interval. This is harder to verify cheaply/automatically without webhook infrastructure — at minimum, confirm `get_info().state` transitions match the documented state machine (`Running` → `Paused` → `Running`), and treat the "not billed while paused" claim as still doc-only (⚠) unless a webhook or console usage check is set up.
9. **Background command cross-process reconnect (eval scenario 5).** Start a `commands.run(..., background=True)` job with output redirected to a file, get the `pid`, create a **second** SDK process/script, `Sandbox.connect(sandbox_id)` from it, `commands.connect(pid)`, `wait()`, and confirm the file read afterward has the full expected output — and separately confirm that the streamed `onStdout` callback registered in the *first* process does NOT receive output once observed only from the second process (or rather, confirm the second process gets nothing via streaming and must read the file).

## Priority 3 — filesystem and networking specifics

10. **`files.write()` batch-form asymmetry (references/filesystem.md).** Confirm Python actually requires `write_files()` for a list of `{path, data}` dicts and that calling `files.write()` with a list either errors clearly or behaves unexpectedly (currently marked ⚠ unconfirmed) — this is a concrete "documentation implies X, does the SDK actually enforce it" check.
11. **Pre-signed upload/download URL flow.** Create a sandbox with `secure=True`, generate an `upload_url`, POST a file to it from outside the SDK (e.g. plain `requests`/`curl`), confirm the file lands in the sandbox via `files.read()`. Also confirm what happens calling `upload_url()` on a sandbox **without** `secure=True` (currently unconfirmed error behavior).
12. **Public URL + `getHost(port)`.** Start a trivial HTTP server (`python -m http.server`) in a sandbox, background it, hit `getHost(port)` and confirm the URL resolves and serves the expected content — cheap and already half-covered by E2B's own quickstart example, worth a real run regardless.
13. **`allowPublicTraffic: false` token gating.** Confirm a request without `e2b-traffic-access-token` really gets `403` and one with the token gets `200`, per `references/networking.md`.

## Priority 4 — lower priority / higher cost or lower likelihood of being wrong

14. **Continuous-runtime cap behavior at the boundary.** What actually happens when a Hobby-tier sandbox hits its 1-hour continuous-runtime cap while still active (auto-pause? auto-kill? an error?) — currently flagged as undocumented in `references/lifecycle-and-cost.md`. Testing this costs a full hour of a running sandbox (~$0.11 at default size) and should be scheduled deliberately, not run accidentally.
15. **Filesystem-only pause/snapshot (`keepMemory: false`) cold-boot behavior.** Confirm memory state is genuinely lost and the sandbox reboots on resume, vs the default pause which the docs claim restores loaded variables/processes.
16. **Forking (`sandbox/fork`) API shape.** This skill did not deep-read `docs.e2b.dev/sandbox/fork.md` beyond the index summary — read it properly and add a `references/` entry (or fold into `lifecycle-and-cost.md`) once confirmed, since it's currently just a pointer with no method signatures.
17. **Errors-and-limits HTTP error envelope.** Once Priority-1 item 4 above is done for one endpoint, extend to a handful of other REST calls (e.g. malformed sandbox create body, sandbox-not-found on a fake ID) to build out a real error-format table instead of the current "⚠ not confirmed" placeholder.
