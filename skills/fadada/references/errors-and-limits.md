## 1. 怎么判断成功与失败

1. **先解析 JSON body**，再判断——非 200 的响应也带 JSON（探测：`HTTP 401` 时 body 是 `{"code":"100002",…}`）。
2. 成功 = `code == "100000"`（**字符串**）。
3. 文档："除特殊说明 HTTP 状态码情况下，错误码默认都是在 HTTP 状态码为 200 的前提"下返回；但表里 `100001` 标 500、`100002`/`100006`/`213xxx` 标 401、`100004` 标 403。
4. 文档要求"根据返回码 code 来判断，而不应该依赖 msg"——**`100001` 是例外**，见 §3。
5. 把响应头 `X-FASC-Request-Id` 连同 code / msg 一起打日志。

## 2. HTTP 状态码

| HTTP | 描述（文档原文） | 建议 |
| --- | --- | --- |
| 200 | 处理成功（业务错误也在 200 下返回） | 看 code |
| 401 | 未授权 | 凭证失效或用户未授权应用 |
| 403 | 异常请求，或请求过于频繁 | 检查参数 / 降频 |
| 404 | 请求的资源不存在 | 检查 URL（无凭证探测：token 无效时拼错的路径也返回 401/100002，不会是 404） |
| 500 | 系统错误 | 按接口错误指引重试 |
| 502 | 服务下线，暂时不可用 | 稍后重试 |
| 503 | 服务不可用，过载保护 | 稍后重试 |

**两条和文档不一致的探测结果**：

- 缺鉴权头不是 `100010`，而是 `100012`（msg 指出缺哪个头）。代码里别只写 `if code == "100010"`。
- `100001` 不只是"系统异常请稍后重试"：AppId 无效、时间戳过期也是它，而且是 HTTP 200。**遇到 100001 必须看 msg**，否则会对配置错误无限重试。

## 9. 限流与各类限制

| 项 | 限制（文档原文） |
| --- | --- |
| 接口 QPS | 每个集成应用对**单个接口**默认 20 次 / 秒（工具能力服务类接口除外） |
| `X-FASC-Timestamp` | 与平台时间偏差 ≤5 分钟 |
| `X-FASC-Nonce` | ≤32 字符，10 分钟内不能重复 |
| accessToken | 7200 秒，调用任何接口续期 2 小时；有效期内重复获取返回同一 token；"不能过度频繁调用"；预留 512 字符 |
| 签署任务文档 / 附件 | 各 ≤50 份 |
| 水印 | ≤5 条 |
| 参与方要求上传的附件 | 每参与方 ≤50 条 |
| 单文件大小 | ≤50M（营业执照 `auth` 用途 ≤5M） |
| `/file/process` | 每次 ≤10 份；文件 ≤1000 页；图片与非图片不能混批 |
| 催办 `/sign-task/urge` | 每天最多 2 次，间隔 ≥2 小时 |
| 列表分页 | `listPageNo` 从 1 开始；`listPageSize` 默认 100、最大 100 |
| 回调 | 3 秒超时；失败重试间隔 3m / 30m / 8h |
| 字段长度 | `signTaskSubject` ≤200、`transReferenceId` ≤128、`actorId` ≤32、`docId`/`attachId` ≤64、`docFileId` ≤32、`clientUserId`/`clientCorpId`/openId ≤64 |

各类链接的有效期见 [sign-tasks.md §19](sign-tasks.md#19-链接与时效汇总)。

## 10. 重试策略建议

| code / 情况 | 是否重试 | 做法 |
| --- | --- | --- |
| `100000` | — | 成功 |
| `100001` + msg「请求已过期」 | 修正后重试 | 服务器校时；每次请求现生成时间戳 |
| `100001` + msg「未获取有效的平台信息」 | **不重试** | AppId 错误或环境错配（UAT / 生产） |
| `100001` 其他 msg | 退避重试 | 文档："请稍后重试" |
| `100002` | 重试一次 | 重新换 accessToken 再发 |
| `100003` | 不重试 | 签名实现有误：检查两步派生、排序、bizContent 是否与发送的一致 |
| `100004` / `100020` / HTTP 403 | 退避重试 | 指数退避，控制在 20 QPS / 接口以内 |
| `100006` | 不重试 | token 与 AppId 不匹配，检查是否混用了应用或环境 |
| `100010` / `100011` / `100012` | 不重试 | 修参数 |
| `100016` | 不重试 | 去控制台配置 IP 白名单 |
| `213xxx` | 不重试 | 引导用户授权 |
| `211058` / `2120xx` | 不重试 | 用量 / 计费问题，联系法大大 |
| `211407` / `200001` / HTTP 500/502/503 | 退避重试 | — |
| 网络超时（创建类接口） | 谨慎 | 先用 `transReferenceId` 在 `/sign-task/owner/get-list` 查一下是否已创建，避免重复建任务 |

## 11. ⚠ 汇总

- `100010` 与实际缺头返回的 `100012` 不一致；`100001` 实际 HTTP 200 且含多种原因（§3，探测证实，已用 Gap 标记）。
- `100009 不允许重复请求` 的触发条件未说明（§3）。
- 错误码表整体未标明哪些码对应哪个 HTTP 状态（多数空白），实际状态码以探测为准：100001 为 200、100002 为 401。
