## 1. 怎么判断一次调用成功

- 文档：「所有接口在调用失败时返回包里都有errcode、errmsg（部分接口在调用成功时没有返回errcode和errmsg）。开发者需**根据errcode存在且不为0判断为失败，否则为成功**」。errmsg「仅作参考，后续可能会有变动」，不能拿来 `if "ok" in errmsg`。
- 无凭证探测（2026-09-11）：各种失败（40013 / 40014 / 41001 / 41004 / 44001 / 93000）的 **HTTP 状态码都是 200**；
  失败响应**仍然带着该接口的默认空字段**，例如 `GET /cgi-bin/user/get` 失败时返回 `"department":[],"order":[],...`，
  `externalcontact/list` 失败时返回 `"external_userid":[]`。只判断“字段在不在 / 列表是否为空”会把失败当成“没有数据”。
- 无凭证探测（2026-09-11）：**路径写错时是 HTTP 404 + 空 body**，`resp.json()` 会直接抛异常——先 `raise_for_status()` 再解析。
- 请求 JSON 不合法时，接口可能不报错而是在 errmsg 里带 `Warning: wrong json format.`，此时参数可能被部分解析（90313 开头说明）。
- **部分成功**：发应用消息、标签增删成员等接口在“部分接收人非法”时返回 `errcode: 0` 并附 `invaliduser` / `invalidparty` / `invalidlist` 等字段；
  **全部**非法才报错（发消息 81013、标签 40070）。成功分支也要检查这些字段。
- errmsg 通常形如 `invalid corpid, hint: [1789...], from ip: x.x.x.x, more info at https://open.work.weixin.qq.com/devtool/query?e=40013`
  （无凭证探测 2026-09-11；部分接口的 40014 不带 hint）。`hint` 可拿去错误码查询工具查。

## 2. 频率限制总表

| 维度 | 限制（文档原文） | 超限后 |
|---|---|---|
| 基础频率 · 每企业 | 调用**单个** cgi/api 不超过 1 万次/分、15 万次/小时 | 按分钟拦截屏蔽 60 秒，按小时拦截屏蔽 60 分钟 |
| 基础频率 · 每 IP | 单个 cgi/api 不超过 2 万次/分、60 万次/小时 | 同上 |
| 第三方服务商 · 每 IP | 单个 cgi/api 不超过 4 万次/分、120 万次/小时 | 同上 |
| 发应用消息 | 每应用不超过 **账号上限数 × 200 人次/天**（一次发 1000 人算 1000 人次）；每应用对同一成员不超过 30 次/分、1000 次/小时，**超过部分被丢弃不下发** | 丢弃不报错；发消息频率不计入基础频率 |
| 应用推送群聊消息 | 每企业所有应用发群消息不超过 2 万人次/分、30 万人次/小时（100 人的群发一次算 100 人次）；每成员在群里收应用消息不超过 200 条/分、1 万条/天，**超过被丢弃（接口不会报错）** | 静默丢弃 |
| 应用创建群聊 | 每企业所有应用累计创建群 ≤ 1000/天；变更群 ≤ 1000/小时 | — |
| 群机器人（消息推送） | 每个消息推送 ≤ **20 条/分钟**（99110） | — |
| 创建账号 | 每企业创建账号数 ≤ 账号上限数 × 3 / 月 | 按月拦截屏蔽 30 天 |
| 创建应用 | 每企业最多 300 个应用；创建次数 ≤ 900 次/月 | — |
| 可信域名 | ≤ 20 次/月 | — |
| 获取打卡数据 getcheckindata | 每企业 ≤ 600 次/分 | — |
| 获取审批数据（旧）getapprovaldata | 每企业 ≤ 600 次/分 | — |
| 审批新接口 gettemplatedetail / applyevent / getapprovalinfo / getapprovaldetail | 各页写「接口频率限制 600次/分钟」 | — |
| jsapi_ticket | 每企业每小时 ≤ 400 次，单应用 ≤ 100 次 | — |
| 上传图片（永久） | 每企业每月 ≤ 3000 张，每天 ≤ 1000 张 | — |
| 手机号换 userid | 出错次数超过企业规模人数的 20% → **1 天不可调用** | 按天屏蔽 |
| debug=1 模式 | 同一 api 每分钟 ≤ 5 次 | — |
| gettoken | 「不能频繁调用…否则会受到频率拦截」；secret 错多次 → **同一 IP 禁用一小时** | ⚠ 文档未说明具体阈值 |

- 「按天拦截则被屏蔽一天（自然天），按月拦截则屏蔽一个月（30天，非自然月），按分钟拦截则被屏蔽60秒，按小时拦截则被屏蔽60分钟」。
- 「根据code获取成员信息 /auth/getuserinfo 若 code 合法则不受上述频率限制」。
- 并发：`45033` 接口并发调用超过限制（如“获取企业客户列表”等取存储数据的接口，对同一企业同一接口限制并发数；对同一 media_id 持续调“获取临时素材”也会触发）；
  `45035` 并发操作冲突（如同时给同一组客户和成员打标签、同时为某成员分配客户）。并发数上限 ⚠ 文档未说明。
- 部分频率拦截可自助解封：`https://open.work.weixin.qq.com/wwopen/devtool/checkCorpSpamBlock`。
- 调用建议（90236）：「大部分企业应用在每小时的0分或30分触发推送消息，容易造成资源挤占…建议尽量避开这两个时间点」。

## 3. 按场景分组的错误码

### 3.1 鉴权 / 凭证

| errcode | 说明 | 排查要点 |
|---|---|---|
| -1 | 系统繁忙 | 稍后重试，**重试不超过 3 次** |
| 40001 | 不合法的 secret | 未传 / corpid 与 secret 不匹配 / 重置了 secret 未更新 / 应用停用 |
| 40013 | 不合法的 CorpID | 无凭证探测：`corpid=test` 即返回此码 |
| 40014 | 不合法的 access_token | 过期、含非法字符、token 类型不对（access_token / suite_access_token / provider_access_token 不通用） |
| 41001 | 缺少 access_token | **必须拼在 URL 中**；无凭证探测：放 header / body 都报此码 |
| 41004 | 缺少 secret | 无凭证探测：gettoken 不带参数即返回此码 |
| 42001 | access_token 已过期 | 重取 |
| 50003 | 应用已禁用 | 管理端重新启用 |
| 60020 | 不安全的访问 IP | 配企业可信 IP，1 分钟后生效；服务商 IP 不能用于自建应用 |

### 3.2 权限

| errcode | 说明 | 排查要点 |
|---|---|---|
| 48001 | API 功能未授权 | 发票接口需认证且激活人数达 200 等 |
| 48002 | API 接口无权限调用 | ① 写通讯录只能用通讯录同步助手 token ② 通讯录同步 token 不能发消息 ③ **客户联系接口只能由“客户联系”系统应用、或配置到客户联系“可调用应用”列表中的自建应用调用** ④ 应用群聊接口仅自建应用、且可见范围需为根部门 ⑤ 代开发应用取 token 用自建应用的 gettoken 接口 |
| 48009 | 不再允许通讯录同步助手从新增 IP 读取通讯录详情 | 改用自建应用读，或只用 ID 列表接口 |
| 60011 | 指定的成员/部门/标签无权限 | 不在可见范围；或在范围内但无编辑权（如往非本应用创建的标签加人） |
| 81013 | UserID、部门ID、标签ID 全部非法或无权限 | 接收人被删除或移出可见范围 |
| 301002 | 无权限操作指定的应用 | 请求里的 agentid 与 token 所属应用不同 |
| 301055 | 无审批应用权限 / 无审批数据拉取权限 | 自建应用未配置到审批“可调用接口的应用”；离职成员 userid 作筛选也会报此码 |

## 4. 重试策略与统一封装

按错误码分类处理，而不是“失败就重试”：

| 类别 | 错误码 | 做法 |
|---|---|---|
| 可重试 | -1、45033、301026、301057 | 指数退避，最多 3 次（-1 文档建议不超过 3 次） |
| 刷新 token 后重试一次 | 40014、42001 | 强制刷新 token，只重试一次 |
| 频率拦截 | 45009 | **不要立刻重试**；按拦截窗口（分钟级 60 秒 / 小时级 60 分钟）等待，并排查是谁在狂调 |
| 配置 / 权限问题，重试无意义 | 40001、40013、48002、48009、60011、60020、301002、301055、50003 | 直接报警给人处理；40001 若循环重试会触发 IP 封禁一小时 |
| 参数问题 | 40003、40035、40058、40063、44004、45002… | 修代码 |

```python
import time, requests

BASE = "https://qyapi.weixin.qq.com/cgi-bin"
RETRYABLE = {-1, 45033, 301026, 301057}
REFRESH = {40014, 42001}

class WeComError(RuntimeError):
    def __init__(self, path, data):
        self.errcode, self.errmsg, self.data = data.get("errcode"), data.get("errmsg"), data
        super().__init__(f"{path}: {self.errcode} {self.errmsg}")

def wecom_call(tok, method, path, *, params=None, json=None, max_retry=3):
    """tok: 带 get(force=False) 方法的 token 缓存对象（见 access-token.md）。"""
    refreshed = False
    for i in range(max_retry + 1):
        q = dict(params or {}, access_token=tok.get(force=refreshed and i > 0))
        r = requests.request(method, f"{BASE}/{path}", params=q, json=json, timeout=15)
        r.raise_for_status()                     # 路径错 → 404 空 body
        data = r.json()
        code = data.get("errcode", 0)
        if code == 0:
            return data                          # 注意：仍需自行检查 invaliduser 等部分失败字段
        if code in REFRESH and not refreshed:
            refreshed = True
            continue
        if code in RETRYABLE and i < max_retry:
            time.sleep(2 ** i)
            continue
        raise WeComError(path, data)
```
